# Improvement backlog

Candidates retain source, problem, evidence, impact, risk, estimated effort, confidence and OPEN/SELECTED/DONE/BLOCKED status. An operator may add candidates through the authenticated API. Initial low-risk seeds concern recovery documentation, provenance and budgets; they are setup observations, not invented discovered failures. Models analyze bounded source excerpts before proposing a change.

The selection routine uses eligible open candidates with retained dimensions; it does not claim a single score establishes objective value. Failed tests, TODOs, performance findings, UI friction, security findings, repeated confusion, journal questions and disagreements can supply evidence through candidate creation. Automatic scanners for every source are not implemented.

Each proposal records problem/evidence/change/benefit/downside/components/risk/reversibility/tests/rollback/cost/permissions. The control plane allows only current low-risk write_docs scope. More sensitive proposals are denied or retained for human review. Human approval cannot override the underlying scope or grant dangerous authority. Outcome and rationale remain separate records; no model self-training or fine-tuning occurs.
